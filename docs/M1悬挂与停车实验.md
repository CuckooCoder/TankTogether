# M1 有限悬挂与停车实验

日期：2026-10-12。依据 V12 的 D-02/03/04/06/07/11、F-01/04/06，以及 V0.2.2 尺寸运动基线。顺序为先最小物理实验、再主策划试玩，不扩展 M3 三关。

## 本轮假设及边界

- 保持现有定长抓取关节与角色实体碰撞，先测其是否足以完成踩空保持、队友拖回、松手坠落；不新增自动脱手或传送救援。
- 使用既有按键驶入四支架、停放、重新抓取并驶离。不增加放下按钮、吸附或自动扶正。
- 候选停车检测为同一组四根支架均有真实顶部接触，缸线速度≤0.10m/s、角速度≤0.10rad/s，连续0.20秒。这些是可调的技术试验值，**不激活检查点、不保存进度、不是主策划已批准的最终停稳门槛**；不要求松左键。
- 当前头部抓取关节限距0.12米沿用基线，仅代表本次短距离悬挂试验，不能据此宣称已解决长悬挂、手臂表现或所有复杂地形。
- 场景 `M1InteractionLab` 与已有 M0/Steam 实验分开。F5停车平地，F6真实坑洞；R重置当前实验。所有人为摆放仅用于初始化与反例，正例通过原角色输入、刚体和关节完成。

## 验证计划

1. 空中经过停车位不能形成承托；仅两根支架不能形成四点候选。
2. 从起点靠移动/跳蹲/抓取松手进入目标支架，停好后可再次抓取并离开；没有新按键。
3. P4进入真实坑洞，其余三人保持地面支持。观察脚底高度、头部与局部锚点距离、平台穿透及持续抓取状态。
4. 另外三人后退，P4不输入移动，检验能否被救回地面；无瞬移、重置或自动松手。
5. 坑洞上松手，验证本人坠落重生，其余三条抓取关系及鱼缸不被重置。
6. 编辑器与 Windows 独立运行同一组检查，保留失败和修正记录、有效截图与可试玩包。固定输入不替代多人手感或异地验收。

## 实验结果与限制

- 编辑器12/12、Windows独立程序12/12；Windows构建Succeeded，0 errors。
- 停车：从起点通过输入驱动，到目标z约5.35形成四点承托（目标中心z=5.50）；松手蹲下入位、站起重新抓取后仍承托，随后移至z约9.60脱离支架。检测器不读取抓取键作为必需条件。
- 反例：悬空时mask=0不成立，仅两根柱时mask=3不成立；起点支架与目标支架分组，不混算四点。
- 悬挂正例：P4刚踩空时停止深入，保持约1秒，脚底最低约-0.52米，最大头部—锚点距离约0.123米，未测到P4对平台的穿透。三人后退、P4没有移动输入，可被拖回地面并持续抓取。
- 松手坠落：P4回到起点，其余三条抓取保持，鱼缸未重置；鱼缸仍有自然位移，未清零或锁定其状态。

**不能抹去的失败边界：** 最初让队伍深入坑洞并长时间等待，会失衡倾倒，报告保留为 `m0-evidence/m1-first-failure-20261012.json`。把P3站位前移0.30米单独尝试，也没让该长等待条件成功。最终通过的是更窄的“刚踩空后及时停止、约1秒后救援”路径，不代表修复了任意站位下的长期静态悬挂。当前F6初始实验站位保留P3前移0.30米，其余场景不变；不锁住任何抓取位置。

本轮没有改核心刚体运动参数、没有增加扶正力或自动救援。停车/悬挂环境由可选实验组件创建，原M0和Steam场景不加入该组件。新增接触观察器使用真正碰撞法线过滤顶部接触，睡眠刚体保留接触直至退出，候选不写存档。

UI截图检查发现Unity重载后缓存GUIStyle可能非空但样式丢失，已标记不序列化并校验字体/字号后重建。截图改为帧末实际取图，避免截图请求尚未完成就重置场景；最终停车、悬挂、救回画面已查看，文字可读。
