# 搬鱼缸 M0 本地交互试玩

日期：2026-10-10。这个版本用于验证重力、头顶支撑、自由抓取和搬运响应。其他三人是可切换的模拟输入，不是联网真人或正式 AI 队友；场景、美术和参数都属于实验资源。

## 打开与操作

Windows 程序位于总目录下 `Unity/TankTogether/Builds/M0CarryLab/TankTogether-M0.exe`。必须保留旁边的 Data 文件夹、UnityPlayer.dll 等文件，不能只拷贝 exe。

进入后点击“开始操作”或按 Enter；鼠标控制视角，Esc 释放鼠标并解除实验抓取。按 R 随时回起点。默认是四人同向模拟，按住左键再按 W 即可开始搬运。

| 操作 | 功能 |
|---|---|
| WASD、鼠标 | 按镜头水平朝向移动，鼠标转动本身不推动鱼缸 |
| 左键 | 在合法底部位置新按下时尝试抓取，按住维持，松开解除 |
| Shift | 奔跑意图，实际位移仍受鱼缸和连接限制 |
| Space、Ctrl | 跳跃、长按蹲下；先搬离支架后观察上下运动 |
| 1 | 单人自由测试，其余三个代理无输入、无抓取 |
| 2 | 其余三人复用你的移动、抓取、跳蹲输入 |
| 3 | 三顺一逆输入测试 |
| 4 | 两侧反向输入测试 |
| Tab | 切换控制角色；仅为本地测试工具 |
| R | 手动回起点、清理速度和抓取关系 |
| Esc、Enter | 释放鼠标 / 开始操作 |

模拟角色不会自动寻路、换位或重新抓取。散开后可用 R 恢复；切换模式或角色属于调试操作，不能作为正式多人操作规则。

## 建议验证顺序

1. 默认模式下抓取后前进、停下、后退，感受响应和重量；先不撞红色障碍。
2. 搬离四根支架后松开左键，观察绿色“已抓取”解除；头仍接触时可出现黄色“仅头顶支撑”。继续前进可能离开支撑范围，鱼缸会下落。
3. R 重置，按 1。松手走出鱼缸底部，再按住左键走回来：应提示失败，不会自动抓取；松开再按才可重新抓。
4. R 重置，按 3 或 4，再抓取并移动，观察反向输入对整体轨迹的影响；需要时按 R 重试。
5. 四人同向搬离支架后试 Space/Ctrl，观察鱼缸上下变化。红色墙和地面为危险接触，浅绿色支架安全；碎缸后按 R。

反馈时优先描述：哪一步不好控制、抓取状态是否清楚、鱼缸为何倾斜/碎裂是否能理解、有没有持续抖动或弹飞。可以给出模式、按键顺序和位置，方便复现。数值检查不能替代这些体验判断。

## 实现边界

- 重力和鱼缸三轴旋转均开启，没有自动扶正；角色保持直立。
- 头顶承托使用垂直弹簧阻尼接触模型，仅在有效底面和小接触误差范围内施力，不提供水平搬运动力；角色与缸的普通碰撞被过滤，侧身撞缸尚不属于验收范围。玩家之间仍有实体碰撞。
- 抓取点取实际头部投影到底面的局部坐标，没有四角插槽。正常拉扯不主动断开；连接仍有求解误差，不保证所有极端阻挡稳定。
- 临时承重响应按有效抓取者比例的平方降低目标速度，一人仍可极慢移动，没有最低人数开关。该曲线是待试玩调整的实验参数，不是正式数值或已冻结架构。
- 原型使用起点支架与手动 R 重试；没有新检查点激活、完整自动全队复位、悬挂救援关卡、Steam 会话或主机迁移。跌出测试地板的角色回起点；这不证明关卡归队路径已可行。
- 玻璃以透明盒和边框展示，破碎先用文字和状态清理反馈，没有正式碎片动画。镜头是基础跟随环绕，尚无完善遮挡处理。
- Esc 或窗口失焦会释放实验输入和抓取，方便在编辑器/桌面切换；不是正式联机掉线逻辑。

## 开发复现

Unity 菜单 `Tank Together > M0 > Open Carry Lab` 打开独立场景，Play 后可试玩。`Run Carry Checks` 执行自动物理/交互检查，结果写入 `Logs/m0-carry-checks.json`。Windows 构建使用 `Build Carry Lab Windows`，不会替换 Main 场景或正式构建列表。

独立程序可用 `-m0-autotest -m0-report <绝对路径>` 自动运行同组检查并退出；返回码 0 表示全部通过。需要渲染环境，不用 `-nographics` 代替画面验收。启动参数、构建结果和实测 JSON 保存在 `docs/m0-evidence` 的交付记录中。
