## 1. 实验目的与范围

### 1.1 唯一核心假设

当每名玩家能**自主、连续、持久地调整身体高度**，并通过实际接触和已成立的抓取关系影响鱼缸时，相比原版，玩家在**普通搬运场景**下会出现更多有意义的分工、共同抬升、局部纠偏、误操作、救援与责任归属。

**本次要验证的不是：**“加入 Q/E 后是否能设计更多高门、矮洞关卡”。如果伸缩只有特定解谜机关需要，而对日常搬运没有正向贡献，不足以证明它值得成为常驻核心。

### 1.2 交付范围

- **必做（B0）：**单人连续纵向伸缩；动态外形与碰撞；持续输入与停止后保留高度；地面／空中合法状态；伸缩可视与调试数据。
- **必做（B1）：**伸缩与原有自由／仅头顶承托／已抓取三状态协同；四人共缸受力；受阻、上顶、下拉、可滑动接触、松手重抓；跳跃、掉落、有限悬挂与原版失败／复位流程兼容；实际可测试。
- **仅在已有网络条件下接入并验证：**四端共享人体实际高度和鱼缸权威运动；不得将本地模拟当作 V12 的 M2 正式异地验收。
- **不要求：**新三关、美术动画成品、成长/技能系统、身高冷却和耗能机制、全新环境机关、世界观设定、重新设计原版 A、为证明有效而脚本强制倾斜鱼缸。

### 1.3 A/B 版本控制

| 项目 | A：原版（对照组） | B：伸缩实验版 |
|---|---|---|
| 移动、跑步、跳跃、左键抓取、鱼缸、物理与场景 | 沿用同一版基线 | 尽量保持一致 |
| Ctrl | 原版蹲下 | **禁用原蹲下高度功能** |
| Q/E | 无身高控制 | Q 持续长高／E 持续变矮 |
| 默认出生身高 | 1.70 m | 1.70 m |
| 鱼缸与危险接触、检查点、复位 | V12 规则 | V12 规则，不改 |
| 记录要求 | 构建、物理参数、操作和结果 | 除左侧内容外记录伸缩参数／状态 |

**交付原则：**优先使用功能开关、独立分支或独立构建切换；禁止在 A 中直接覆盖 Ctrl/角色身高控制后丢失干净对照组。程序提交时须写明两版具体构建号、共用物理参数版本与已知差异。

## 2. 首轮尺寸与运动参数

### 2.1 沿用的 V0.2.2 基线（不是本次新定）

| 项目 | 第一轮值 | 备注 |
|---|---:|---|
| Unity 比例 | 1 单位 = 1 m | 研发建议 |
| 鱼缸长 × 宽 × 高 | **3.20 × 2.20 × 0.95 m** | 不因伸缩自动改变鱼缸几何或质量 |
| 普通站高／开局身高 | **1.70 m** | 两版共用出生高度 |
| 人物水平碰撞直径 | **0.60 m** | 伸缩版暂不更改宽度／胖瘦 |
| 鱼缸普通水平承托的缸底离地 | **1.70 m** | 缸顶约 2.65 m；非永远锁定高度 |
| 单人步行／奔跑目标 | **4.0 / 6.0 m/s** | 受鱼缸和队友约束时实际速度可低于目标 |
| 四人稳定携缸／奔跑目标 | **2.5 / 3.5 m/s** | 原版调试目标，不是锁速 |
| 单人原地跳高目标 | **0.65 m** | 运动基线，尚待实机确认 |
| 四人协调缸底抬升目标 | **0.55 m** | 原版试验目标，**不保证**伸缩叠加后一定达到 |
| 原版 Ctrl 蹲下高度 | **1.10 m** | **只在 A 保留 Ctrl 操作**；B 的最低高度恰好取此值 |

### 2.2 本次新增、主策划同意作为实验起点的参数

| 参数标识（建议） | 起始值 | 调整/含义 |
|---|---:|---|
| `DefaultHeight` | **1.70 m** | 角色出生／重生／鱼缸碎裂复位恢复高度 |
| `MinHeight` | **1.10 m** | 角色实际可达到的最低高度，不低于下限 |
| `MaxHeight` | **2.30 m** | 角色实际可达到的最高高度，不高于上限 |
| `GrowRate` | **0.30 m/s** | 无阻碍持续按 Q 的目标伸高速率 |
| `ShrinkRate` | **0.30 m/s** | 无阻碍持续按 E 的目标缩矮速率 |
| `Width/Radius` | 直径 **0.60 m** | 实验版身高变，水平碰撞体直径不随之变化 |
| `AutoReturnToDefault` | **false** | 松开 Q/E 后**不自动恢复**默认身高 |
| `MaxHoldDuration` | **无限制** | 无技能计时、无 CD、无体力/能量耗费 |
| `QAndETogether` | **停止主动伸缩** | 两键输入互相抵消，不以按下先后决定方向 |

计算说明：从 1.70 m 到 2.30 m 或 1.10 m，在完全无阻碍时均约需 **2.0 s**；从最低到最高约 **4.0 s**。这些是**候选调试数值**，不是性能指标，也不保证多人抓取时一定能达到目标高度。

**必须可调但不在本案强制填写假数值：**伸缩最大推/拉作用、支撑约束强度、抓取约束刚度／顺应性、人物相对鱼缸可允许的姿态变化、头部接触／滑动摩擦系数、伸缩加减速与碰撞响应、空中伸缩限制、网络校正和平滑参数。程序选择技术表达和试验区间、回填测试结果；策划验收外在表现。

### 2.3 首轮场景的空间要求

- 基础受力试验场使用**安全、宽敞、顶部净高充足**的空白平台，避免伸缩初测因非目标障碍频繁碎缸。建议首轮可调顶部净高**至少 5.0 m**，这是**试验场景建议**，不是全游戏关卡硬规则。
- 另做**明确标记的危险天花板**和危险侧墙测试区，用于验证真实触碰即碎；不可为了在低顶区运行而全局关闭危险判定。
- 估算：若水平鱼缸从缸顶 2.65 m 整体上升 0.60 m，则顶面约 3.25 m；若再与原版 0.55 m 协作跳升目标简单叠加，可能接近 3.80 m，倾斜外角可能更高。**仅为几何风险估算，不代表物理保证**。

## 3. 操作需求（S-01～S-04）

### S-01｜键位（已确认）

| 输入 | 实验版 B 的行为 | 与原版差异 |
|---|---|---|
| `W/A/S/D` | 相对独立镜头水平朝向移动 | 沿用 |
| 鼠标移动 | 转动第三人称镜头 | 沿用 |
| `Shift` 长按 | 奔跑意图 | 沿用 |
| `Space` | 仅本角色主动跳跃 | 沿用；不触发其他玩家自动跳跃 |
| 鼠标左键**按下瞬间** | 满足原版合法条件则建立抓取；继续按住维持；松开解除 | 沿用 D-01/D-02/D-05 |
| 鼠标右键 | 不提供抓取切换 | 沿用 D-05 |
| **`Q` 长按** | **持续尝试长高** | **新增** |
| **`E` 长按** | **持续尝试变矮** | **新增** |
| **`Ctrl`** | **实验版不执行原蹲下/下拉高度功能** | **仅 B 明确覆盖；A 不变** |
| 鼠标滚轮 | 镜头缩放按原版实现情况 | 不新增强制要求 |

不修改左键抓取的**按下瞬间判定**。例如玩家在 1.10 m 高度时够不到缸底，在范围外先按住左键，之后长高进入抓取范围，**不会自动抓住**，必须松开左键再按下。

### S-02｜连续伸缩（已确认）

1. 按住 Q：逐渐按 `GrowRate` **尝试**长高，直到松开、碰到实际限制或达到 `MaxHeight`。
2. 按住 E：逐渐按 `ShrinkRate` **尝试**变矮，直到松开、碰到实际限制或达到 `MinHeight`。
3. 松开 Q/E：停止本次**主动伸缩输入**，保留**实际达到的身高**；由于多人作用，鱼缸、角色整体运动和连接的被动动力学不必立即停止。
4. Q+E 同时按住：人物不执行主动高矮变化；不增加额外模式。
5. 到达极限后持续按键：保持极限，不发生越界；不积累超过边界的隐藏位移。
6. 身高不定时回弹、不因抓取或松手自动重设、不因停止移动而恢复；无使用次数和时间上限。
7. 物理受阻时，人物的实际伸缩可慢于 0.30 m/s，甚至停住；若松键时实际只达到 1.83 m，则**保持 1.83 m**，不在障碍解除后自行“补发”未完成的伸长。若障碍解除时 Q 仍按住，可继续尝试伸长。

### S-03｜伸缩的视觉与碰撞同步（已确认行为，技术实现自主）

- 是**人物身体纵向伸缩**，不是等比例放大缩小、不是技能特效，也不是鱼缸直接升降键。
- 站在地面时，脚部尽量维持与地面的有效支撑，头顶高度随人物实际身高改变；外观、角色有效碰撞体、头部支撑位置应相互对应。
- 身高变化过程对本人和队友**可见、可理解**，不能瞬间跳到另一个档位；视角／镜头应尽量保持第三人称可读性。
- **身高变化不改变水平碰撞直径，不自动改变速度、跳跃目标能力、角色质量或抓取判定原则。**
- 身高变化不得产生角色与地面／墙体的虚假穿插或“碰撞体变了但模型没变”的长期偏差。

### S-04｜运动能力不随身高变化（已确认）

无论高矮，沿用 A 的步行、奔跑、跳跃**目标能力**。实际结果仍受碰撞、抓取、鱼缸重量、其他玩家及物理环境约束。不得因为角色长高就自动加速、自动多跳、自动提高跳高；也不因变矮自动减速。不得把伸缩改造成可以无限提升角色整体高度的主动位移/飞行能力。

## 4. 角色／鱼缸状态与受力（S-05～S-11）

### 4.1 状态总表

| 当前状态 | Q 长高 | E 变矮 | 对鱼缸允许的作用 | 禁止的行为 |
|---|---|---|---|---|
| 自由：没有抓取且没有有效头顶接触 | 身体变高 | 身体变矮 | **无接触则不影响鱼缸** | 隔空顶升、隔空抓取、隔空牵引 |
| 仅头顶支撑：未抓取，有合法头部接触 | 可通过真实接触**向上承托／顶升** | 减少或失去承托 | 重力、法向力、被动摩擦可使鱼缸滑动／倾斜 | 凭 E 主动向下拉鱼缸；凭 WASD 获得与抓取等价的主动水平驱动 |
| 已抓取：保持左键与合法抓取连接 | 可在有限受力条件下**主动上顶或影响倾斜** | 可产生**有限向下牵引**或改变倾斜 | 对局部抓取点施力、与其他玩家共同决定鱼缸运动 | 自动松手、无限拉长连接、无条件拉高／压低鱼缸 |
| 空中／踩空／悬挂 | **允许**调整实际身高 | **允许**调整实际身高 | 仅在抓取或真实接触成立时有限地传力 | 靠伸缩凭空飞行／无限爬升、额外跳跃输入、无限悬挂距离 |
| 死亡／碎缸复位 | 输入清除 | 输入清除 | 旧抓取／支撑和受力清除 | 复位后沿用旧连接、持续伸缩冲量 |
| 系统确认断线 | 移除该玩家有效伸缩施力 | 同左 | 无持续支撑、抓取、作用与实体阻挡 | 幽灵施力、偷偷重置鱼缸惯性 |

### S-05｜支撑与抓取的核心区别（已确认）

1. **未抓取但头顶接触：**角色长高，头部可真实向上推动鱼缸；角色变矮，头部可以逐渐失去支撑。鱼缸是否滑动、倾斜、掉下，由支撑位置、接触、摩擦、重力、惯性和其他玩家决定。
2. **已抓取：**固定的鱼缸局部抓取点提供受限双向连接。玩家长高可以向上作用于对应部位；变矮可以在允许的物理范围内向下牵引。**抓取点不因角色变矮就沿底面滑动**。
3. **抓取 ≠ 永远锁死鱼缸：**抓住后“不会像未抓取头顶承托一样在头部自由滑落”，不等于鱼缸对全部位移／旋转免疫。其他玩家、重力、碰撞与现有运动依然有效。
4. 已抓取变矮后，即使头部离开鱼缸底部，只要仍处在原版有限合法的抓取关系中且左键未松开，**不能仅因头部不接触就解除抓取**；不得出现无限长隐形绳或手臂。
5. **角色的实际身高变化与抓取距离、人物位置必须联立求解。**如果抓取者被阻挡或鱼缸受约束，优先限制实际伸缩／角色整体移动／鱼缸运动，不能靠拉伸连接或瞬时位置修正掩盖问题。

### S-06｜单人伸缩与多点竞争（已确认）

- 四名玩家站位不固定；底部任意合法位置可以抓取。人的站位越分散，一人施加的垂直作用一般越容易表现为可观察的局部力矩；越集中，多个约束越容易相互抵消或限制伸缩。
- **案例：**四个人都在鱼缸中央，三人不按 Q/E，只有一人持续 Q：此人**可能只增长很少、增长受阻或带动其他已抓取者／鱼缸整体移动**；**不保证能达到最高 2.30 m**，也不硬编码必定倾斜多少角度。
- 四人站在四个分散的合法位置，只有一人长高：若约束允许，应能观察到该局部支点对鱼缸的上顶、旋转趋势或其他可理解的反作用；**不保证每次必然倾斜**。
- 一人变矮、三人高度不变：可能发生有限下拉、支撑减少、鱼缸受重力下沉／倾斜；也可能被其他玩家约束而无法继续变矮。**三人不输入 ≠ 三人被世界固定**。
- 没按 Q/E 的已抓取玩家，其**自身身高保持**，但整体角色可按原版 D-04 被鱼缸被动拖动、抬起或短暂离地；遇墙体／地形应合法受阻，不得穿模或爆炸。
- 任何时候，不能用“多数人直接否决少数人”的脚本，也不能用“只要有人 Q，鱼缸就强制朝他那侧旋转”的脚本代替受力。

### S-07｜松手后长高导致的滑动／滑落（已确认）

- 玩家松开左键，**立即移除主动抓取连接**（D-01/D-05）；若头顶仍与缸底真实有效接触，则按仅支撑处理。
- 此时长高可使头部向上顶起鱼缸，但头部不再具备固定抓取点的防滑约束；鱼缸**可能**沿支撑者头顶相对移动、倾斜、滑落，或在其他人支撑下保持相对稳定。
- 是否滑落由真实接触、倾斜、摩擦、重力、惯性与队友作用共同决定，**不得固定脚本为“未抓取＋长高必滑落”**。
- 松手不清除鱼缸已有线速度、角速度和倾斜；未抓取的人不因鱼缸运动而获得 D-04 的主动抓取式水平拖动。
- 程序可对接触求解做必要稳定措施，但不得通过隐藏黏附把仅支撑变成永久抓取，也不得给未抓取头部施加等同 WASD 搬运的主动水平动力。

### S-08｜受阻和边界碰撞（已确认）

1. 人物头部／身体自身顶到实体天花板或障碍，但**鱼缸未碰危险物**：限制人物实际长高；人物碰撞本身不自动认定鱼缸失败。
2. 人物长高把鱼缸推向**危险天花板、墙面、地面或硬质障碍**，鱼缸可见外表面真实有效接触：**立即碎缸，执行原版最近检查点复位**（D-07）。**不得在即将真实接触时自动隐形阻止鱼缸接触来规避失败**。
3. 鱼缸与玩家头顶、合法抓取以及四根棉花安全支撑接触：按原版合法例外，不能误碎。
4. 一个玩家持续 Q/E，因其他三人／鱼缸／环境而无法进一步伸缩：实际伸缩可减慢或停住；这本身是正常受限玩法，**不视为严重技术卡死而自动重置**。
5. 异常高冲量、胶囊穿模、无人施力弹飞、无法解释的强制位置跳跃，应作为**程序缺陷**调查，不当作搞笑玩法。

### S-09｜地面、空中、跳跃与悬挂（已确认方向，技术约束待验证）

- **有稳定地面支撑时：**人物以脚底为主要支点纵向伸缩，允许通过头顶接触或抓取对鱼缸施力；若已抓取并被鱼缸拖动／抬起，应遵守原版相互约束与被动带动，不要求角色永远钉死地面。
- **起跳与腾空时：**Q/E 仍可改变角色实际体型；不会再次触发 Space 跳跃。只有当角色和鱼缸有**已存在的合法抓取关系或实际有效接触**时，动作才可传递有限的相互作用。
- **不允许飞行漏洞：**禁止通过空中反复 Q/E 在没有外部支撑的情况下不断增加人＋缸系统的净向上动量或高度；程序可采用动量守恒近似、反作用、施力上限或其他稳定方法达成这一外在要求。
- **悬挂：**踩空且未进入死亡区、左键仍按住，可在 V12 D-03 规定的**有限有效抓取范围**内悬挂；伸缩不应直接解除合法抓取，也不能让悬挂距离无限增加。伸缩可能使角色姿态／拉力变化，但允许的实际幅度取决于连接、受力与空间限制。
- **跳跃仍有独立价值：**伸缩不能自动等价于越过所有原本需要跳跃的断层，也不能凭变高跨过角色没有实际踩踏的空隙。关卡是否被绕过由试玩验证，不另加隐藏禁用规则。

### S-10｜人物运动与模型空间（已确认目标）

- 动态调整角色胶囊体、头顶承托判定与角色视觉高度，保持地面站立时位置逻辑一致；保留人物之间的实体互挡。
- 玩家高度不固定为某个任意三档值。`1.10 m～2.30 m` 范围内能够随持续输入**平滑、连续地停在中间高度**，不是离散三档跳变。
- 人物宽度、质量、地面步速／奔跑目标、单人跳跃目标不随当前身高变化（本实验控制变量）。
- 已抓取玩家如果被物理带离地面，应以真实角色与鱼缸的相互约束优先，不能以“脚必须永远贴地”为由把人传送回地面。
- 人物接近 1.10 m 时，不能因碰撞体收缩被塞入本来不存在的封闭空间或强行穿过墙；局部缩放的数值稳定性由程序验证。

### S-11｜合法抓取范围与身高（已确认）

- 抓取只允许在鱼缸**底面任意合法区域、且角色实际可达到的抓取范围内**进行；不能仅因站在缸底的水平投影中就隔空抓取。
- 人物低至 1.10 m 时，若鱼缸缸底仍在约 1.70 m，且实际无法够到抓取点，此次左键按下必须失败并显示原因；可先长高、正常跳跃或让鱼缸物理下降后重新尝试。
- **抓取是否成功仍只在左键按下瞬间检查；按住时长高走入范围不会自动补抓。**
- 已经合法抓住后，允许伸缩改变头部高度并暂时失去直接头部承托，但不得因此无故自动断抓；同时必须维持**有限、可信的手部／抓取点连接**。

## 5. 生命周期、检查点与异常（S-12～S-14）

### S-12｜死亡、碎缸、检查点复位（已确认）

1. **正常游戏状态：**身高持续保存，移动、松手、换位、停车、普通卡角不会自动恢复到 1.70 m。
2. **单名玩家进入死亡区：**仅本人按原版流程解除抓取／支撑，在最近检查点重生；该人身高重设 **1.70 m**；鱼缸、其他玩家的高度和运动状态**不重置**。
3. **鱼缸破碎、全队失败复位：**鱼缸回到最近已激活的四根棉花安全支撑，静止且无旧动量；实际参与复位的角色恢复 **1.70 m**、取消本次伸缩输入、清除旧抓取／支撑／异常力与虚假提示。**不改变 V12 断线后复位在线人数仍待主策划确认的 F-02。**
4. **复位后**，必须再次按下左键才重新建立抓取，不允许复位前长按状态自动抓上；也不允许上一轮 Q/E 按住导致角色出生后自动续长高。输入释放/重新使能的具体工程方式由程序提出，以此外在结果为准。
5. **严重技术异常兜底**继续遵守 D-10，只在可客观确认不可恢复且经原版规则允许的情况下自动复位；普通多人高度拉扯／角色伸缩受阻不得触发。

### S-13｜检查点不变（继承 D-06）

- 四根棉花安全支撑**实际有效承托鱼缸**才可激活检查点。鱼缸经过、仅部分接触、悬浮掠过均无效。
- 伸缩可以成为玩家尝试停放／取走鱼缸的手段，但**不得新增磁吸、锁定对位、靠路过触发、自动扶正**等未经确认的规则。
- 伸缩版也不增加独立“放下/举起”按钮。若发现原版已存在的 F-01/F-06 在该机制下无法成立，程序提出证据，交主策划另行决定，不在本案私改。

### S-14｜断线／联机继承（已确认原则）

- 系统确认某人断线后，该玩家不再提供抓取、头顶支撑、持续伸缩力或实体阻挡；鱼缸当前的运动及其他三人的高度保持，余者可继续（D-08）。
- **联机中实际身高是游戏状态，不是单纯的本地动画。**权威端需要在伸缩输入、实际高度、角色碰撞、抓取/头部接触以及鱼缸运动间保持一致；远端可做视觉插值，但不得出现长期的“看着没接触却顶起鱼缸”或“看着没撞顶却碎缸”。
- 复用原版联机架构和 M2 要求：**四名真人、四台独立电脑、不同互联网网络**才满足原版 M2 验收。实验 B 可以先在本机／受控环境排错，但最终如要并入正式 M2，不能以单机/局域网替代正式测试。
- 断线确认、权威宿主掉线、重连、掉线后碎缸的人员集合等原版未结事项仍按 F-02/F-03/F-09 待评审，不得假装本文件已经确定。

#### 6.1 玩家端可见

## 7. 交付节奏与程序实现自主边界

### B0｜单人身体伸缩沙盒

- 从原版复制或继承角色控制，增设 Q/E 连续伸缩；实验版禁用 Ctrl 蹲下。
- 验证 1.10～2.30 m 的可调身高、无阻碍 0.30 m/s、松键保留、碰撞和可见性。
- 验证地面、普通跳跃、环境阻挡时的角色自身稳定性。
- **阶段结果：**单人伸缩成功，但**不得据此宣布鱼缸受力功能完成**。

### B1｜鱼缸接触与一人上下受力

- 接入未抓取头顶顶升、松手后滑动／可能滑落、已抓取上顶／有限下拉。
- 区分“人物受阻”与“鱼缸触及危险墙/顶→真实碎缸”。
- 校验有效抓取区、只在左键按下瞬间判定与缩矮导致的抓取失败。
- **阶段结果：**证明接触与抓取状态的作用不同，基础力学有因果可读性。

### B2｜四人联立受力与复杂状态

- 重点测四人分散／集中、三人不动一人伸缩、多人反向伸缩、被动拖动、站位变化。
- 叠加原版移动、奔跑、起跳、错时跳跃、落地、踩空悬挂／救援与复位。
- 消除严重非物理爆炸、穿模、无限抓取和明显的无限空中攀升漏洞。
- **阶段结果：**可供策划组织四真人灰盒对照试玩的 B 构建。

### B3｜A/B 对照记录与结论

- 程序提供可重现的 A/B 构建和参数说明；策划组织并负责测试验收、回填体验结论。
- 若实验版纳入正式后续 M2，再按 V12 在不同互联网网络由四名真人检验同步和共享物理。
- **阶段结果：**决定“继续优化伸缩/作为常驻候选/保留后期变化/暂缓或砍掉”，而不是默认 B 胜出。

### 程序技术自主（不授权改变玩家可见规则）

程序可自主决定：

- Unity 角色控制器和可变高碰撞体实现；胶囊底部锚点、脚底接地检测与角色视觉伸缩方式；
- 共用鱼缸的受力模型（真实刚体、受控物理或混合方式），垂直力限制、阻尼、稳定求解；
- 抓取点相对鱼缸固定与双向约束的具体算法；伸缩遇约束的处理方式；
- 头部接触、摩擦、阻挡、垂直推拉、无抓取滑动的参数与诊断工具；
- 空中伸缩与有限悬挂的动量／反作用处理，避免角色和鱼缸获得无依据的净上升；
- 网络权威、输入采集与同步、插值和服务器判定、日志；
- 开发分支结构、调试工具与阶段拆分顺序（但应能独立交付 B0～B3 的可验证结果）。

**禁止技术偷换：**改成按 Q 直接设置鱼缸高度、按 E 强制设置鱼缸倾斜角、长按左键自动重新抓取、未抓取头顶产生等价 WASD 主动水平驱动、用隐形保护层忽略真实危险碰撞，或将普通伸缩冲突当“严重异常”自动送回检查点。

## 8. 功能验收用例

### S-16｜实验版功能与对照验收（已确认验收方向）

> 所有“合格”以**外在行为正确、可复现、可理解**为准。纸面预测的具体倾斜角、抬升厘米数和伸缩极限不作为事先锁定的硬指标。单人/本地测通只能证明对应阶段，不能替代后续四真人共享状态验收。

| 编号 | 条件／动作 | 预期合格表现 |
|---|---|---|
| ST-01 | 自由状态，1.70 m 持续 Q 2 秒，无障碍 | 实际高度连续接近 2.30 m，外观/碰撞同步，无瞬移 |
| ST-02 | 自由状态，1.70 m 持续 E 2 秒，无障碍 | 实际高度连续接近 1.10 m，不低于下限 |
| ST-03 | 在 1.93 m 时松开 Q，保持站立／行走 | 高度保持约 1.93 m；不自动回弹到 1.70 m |
| ST-04 | 从 1.10 m 逐渐 Q 到 2.30 m | 连续变化约 4 秒（无阻碍时），中间任意高度可停 |
| ST-05 | 同时持续按 Q+E | 不发生主动伸缩，也不抖动或突破边界 |
| ST-06 | 反复按 Q/E，长时间停在非默认高度 | 无 CD、耗能、持续时间限制或自动复原 |
| ST-07 | B 版按 Ctrl；A 版按 Ctrl | B 不执行原蹲下；A 完整保留原版蹲下与相关受力 |
| ST-08 | 未抓取、未碰鱼缸，原地 Q/E | 仅改变自己身高，不隔空影响鱼缸 |
| ST-09 | 未抓取，头顶有效承托，逐渐 Q | 可经真实接触向上顶缸，受力来源可解释 |
| ST-10 | 未抓取，头顶有效承托，逐渐 E | 逐渐降低或失去支撑；**不主动下拉**鱼缸 |
| ST-11 | 未抓取，松开左键后持续 Q，鱼缸有倾斜或偏心受力 | 鱼缸可沿头部相对滑动／可能滑落；不强制必定滑落；无隐形固定抓取 |
| ST-12 | 原本合法抓取，持续 Q/E | 对固定抓取点可产生有限上顶或下拉，鱼缸按实际约束运动，不强制角度 |
| ST-13 | 已抓取后变矮，头部不再接触底面 | 保留有限合法连接；普通拉扯不因离开头顶接触就自动脱手，也不无限伸长 |

#### 8.1 策划侧体验观察（不是未经实测就锁死的通过率指标）

同一组四名真人在**相同或等效**的安全平地、单人局部顶升场、简单转向场进行 A/B 对比；尽量控制角色／鱼缸尺寸、物理基线、操作者熟练程度、场景难度。不同小队可采用 A→B、B→A 交叉顺序降低学习效应。记录：

1. 玩家是否在**普通搬运**中主动使用 Q/E，而不仅仅为了专门的高度机关；
2. 是否产生相对 A **新增且可解释**的合作、失误、临场救援与互相指挥；
3. 失误是否真正来自玩家操作，而非物理求解异常／网络错位；
4. 新手能否理解自己的高度变化如何影响鱼缸；新增按键是否造成明显负担；
5. 是否使原本的移动、转向、跳跃、松手换位等操作失去价值；
6. 同场景的失败次数、主动救援次数、无解释异常次数、完成情况及重试意愿；
7. 观看录屏的旁观者，是否能够看懂因谁的伸缩造成哪种鱼缸运动。

#### 8.2 验收与是否采纳，是两个不同的决定

- **功能验收通过：**B 可以稳定、正确地完成 S-01～S-16 的玩家可见要求与适用测试用例；不出现持续无法解释的弹飞、穿模、错误碎缸或无限伸缩漏洞；各测试证据可复现。
- **核心玩法采纳：**功能通过后，仍须由策划对 A/B 真实试玩的乐趣、社交事故、操作负担、传播可读性与成本作单独判断。**本案不预设 B 一定比 A 好玩，也不预设它一定成为正式常驻功能。**
- **失败也可以成为有效实验结果：**若 B 需要高昂的不稳定多点约束成本，或者只在特制机关中发挥价值，允许停止 B、保留 A 或将伸缩作为后续关卡局部变体讨论。

## 10. 一页执行摘要（发给程序先看）

**要做的事：**保留原版 A；新增独立 B 版本，让人物在 `1.10～2.30 m` 之间以首轮 `0.30 m/s` 的速度连续伸缩。`Q` 长高，`E` 变矮，松键保持当前**实际**高度；`Q+E` 抵消；无 CD／耗能／持续时间上限；**B 取消 Ctrl 的原版蹲下功能，A 保留**。不改变人物水平宽度、质量、移动和跳跃基线。

**最重要的物理规则：**伸缩作用在**人**而不是直接作用在**鱼缸**。未抓取头顶真实接触时可向上顶升、缩矮只减支撑且可自然滑动；已抓取时可经**固定、有限**的抓取连接上顶／有限下拉，不能沿缸底自由滑抓取点。四个人同时作用时可能受阻、倾斜、平移或被动带人，**绝不保证一人能无条件长到 2.30 m，更不强制鱼缸必定倾斜**。地面与空中都允许伸缩，但不得通过空中伸缩实现无限飞行。

**不会改的规则：**左键按下瞬间抓取、松开解除；正常拉扯不断抓；合法头顶承托与抓取有区别；已抓取者可以被鱼缸合理带动；有限悬挂；**鱼缸真实碰到危险墙／地／天花板即碎**；四根棉花安全支撑停车式检查点；原版死亡、断线和复位原则；游戏内三类抓取状态反馈与既定联网里程碑。

**交付标准：**程序先做可调灰盒机制并给出 A/B 构建、录屏、参数与用例记录；**策划负责四真人测试与是否采纳决策**。本次不新增完整关卡，不得把伸缩“很适合设计关卡”当作证明它已具有常驻核心竞争力的结论。
