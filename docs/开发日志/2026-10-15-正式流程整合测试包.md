# 正式流程整合测试包开发记录

依据《正式版游戏流程与基础系统策划案 V1.1》、V12 核心规则及用户批准的《正式版局外系统接入方案_20261015》。用户覆盖决定：开局 2～4 人；当前白模最后一组四柱作为测试终点。此次是整合候选包，不是 SYS-001～088 全部正式验收。

## 当前可用流程

启动大厅 → 本地模拟 / Steam 联机 → 选择五个存档之一 → 创建房间 → 码加入或 Steam 邀请 → 非房主准备 → 至少两人加载成功 → 搬运与 Q/E 伸缩 → 四柱检查点 → 失败重试 / 普通成员断线继续及原身份重连 → 最后四柱结算 → 30 秒 MVP / 背锅王投票 → 各自返回 → 换档或确认重新挑战。

本地 A、伸缩沙盒 B0、关卡伸缩 B 均保留；本地模拟不写共同进度。Steam 默认 B，所有成员须选择一致。两人轻度抗翻辅助沿用此前授权。房主故障仍结束会话；没有实现无缝主机迁移。

## 实现与保护

- 真实传输层 Steam 身份、固定席位、锁定名单；重复身份、新人中途加入及本房间被踢身份会被拒绝。普通掉线移除本人实体，不回滚鱼缸；主动离队不保留本局重连资格。
- 15 秒加载超时回原房间并清准备，原 Run 不变。重玩仅在房主和至少一位成员真实进入后提交新 Run；提交失败保留旧档。
- 旧 campaign ID 不变，旧进度显示为第 1 槽。首次新格式写入前保留 `.legacy-v1`；格式 schema2 使旧包明确拒绝，避免静默丢失新增统计。不要交替用旧包写同一存档。
- 五槽独立；新建、选择、重命名、历史详情、最好成绩、二次确认删除。删除当前槽的进度/历史和其备份，不影响其他槽。
- SHA256 校验、临时文件落盘检查、原子替换、上一版本备份、修订号防覆盖沿用。统计每约 10 秒保存，CP/正常退出/结算另行保存；异常退出最多可能丢最后一段尚未落盘统计，不承诺逐帧保存。
- 四柱接触在每个权威物理步结束后裁决；同一步危险优先；系统出生/旧 CP 不重复计数。正常危险碎缸、技术复位、投票复位分别记录。
- 通关事实和待报告同次保存；投票结束再保存最终报告，按 Run ID 去重。异常结束后读取待报告，保留已保存结果、未投弃权。重玩保留历史。
- 候选行为采集跳跃、合法抓取、坠落；历史成员按 Steam ID 聚合，展示中性次数排行。正式趣味称号名称、完整指标与装扮清单未冻结，不自行确定，也不推断碎缸责任人。
- 个人设置与共同存档分离；改键冲突校验、按下沿、Esc 取消、默认绑定二次确认；设置不暂停联网世界。显示模式/分辨率需保留确认，15 秒不确认还原；`-safe-display` 可强制安全窗口。
- 简中/英文主菜单、设置、存档、装扮、结算及主要房间文案已接入。昵称不参与字符串翻译。GM、白模机关标签、部分物理反馈及少数异常详情仍中文，正式发布前需语言全量巡检。
- 装扮使用当前角色及四种帽色，支持预览转身和房间同步；Steam 头像异步读取，缺失时仍显示昵称/席位。

## 房间码技术回填

旧 `FriendsOnly` 无法满足非好友凭码加入。当前改用 Steam Public Lobby，游戏内没有房间浏览或自动匹配；加入需要有效临时房间 ID、相同构建签名，并由房主校验 Steam 身份与席位。Steam 后台 Public 类型可被 API 搜索，因此本轮数字房间号并不是强保密口令，不宣称房间不可被检索；正式商业版本若要强访问凭证需追加私有令牌/邀请设计。

参考：[Valve ISteamMatchmaking / ELobbyType](https://partner.steamgames.com/doc/api/ISteamMatchmaking#ELobbyType)。原 Steam 类型及参数来自固定 Facepunch 依赖，不升级 SDK。
