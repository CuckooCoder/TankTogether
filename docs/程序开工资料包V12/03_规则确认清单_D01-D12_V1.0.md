# 《搬鱼缸》核心玩法规则确认清单 V1.0（D-01～D-12 全部确认）

> **用途**：记录主策划已经明确拍板的玩法边界，不把尚待实验的技术参数伪装为已冻结规则。日期：2026-10-09。
> **适用基线**：核心玩法程序需求策划案 V1.0 + 核心交互规则补充 V1.12；原主文档的其他规则不因此失效。

## 一、已确认决策

### D-01｜预按住左键不会自动抓取 — A（已确认）
- 判定时机：**仅在左键从松开变为按下的瞬间**，检查角色是否位于鱼缸底部的有效抓取区域、是否满足其他合法抓取条件。
- 按下时有效：建立抓取关系；持续按住左键时，按既有抓取规则维持关系。
- 按下时无效：本次按键不建立抓取；继续保持按下状态并走入有效区域，**也不得自动抓取**。
- 再次尝试：玩家必须**先松开，再重新按下左键**，才执行新的抓取判定。
- 已抓取后松开：立即解除主动抓取；如果头部仍保持合法接触，可仅提供头顶支撑。
- 边界：本决策冻结输入触发时机；有效抓取范围的几何尺寸、检测算法、失败提示样式仍属于技术试验和体验验收内容。
- 验收：在范围外按住→进入范围不抓取；松开再按→可抓取；已抓取松开→主动抓取解除，合法头顶接触仍可支撑。

### D-02｜正常拉扯不会自动脱手 — A（已确认）
- 前提：抓取关系已经成立、角色持续按住鼠标左键。
- 规则：一般情况下，四人相互拉扯、朝不同方向移动、碰到障碍产生冲突，不会仅因张力较大自动解除抓取。
- 表现：优先限制角色实际运动、鱼缸平移/偏转，仍要保留不同抓取者的影响；不允许无限伸长连接、穿模或突然弹飞。
- 明确例外：主动松开左键、玩家触发死亡/重生、鱼缸破碎/全队复位。
- 未冻结的技术项：极端不可恢复卡死的兜底方案须记录并经评审；不得混同于正常拉扯。

### D-03｜有限悬挂与救援 — A（已确认）
- 场景：角色抓住鱼缸后不慎踩空或跌出路沿，继续按住左键，尚未进入死亡区。
- 规则：角色可以在**有限、合理且可实现的抓取关系范围**内吊在鱼缸下方，失去正常站姿/头部支撑本身不强制解除抓取。
- 玩法预期：鱼缸受悬挂者与其他抓取者的相互作用，其他队友有机会救援或调整站位；并非保证每次都能救回。
- 明确边界：禁止无限距离拉伸或隔空抓取；进入死亡区立即解除该玩家抓取并执行单人重生，鱼缸和其他玩家保持游戏状态。
- 未冻结的技术项：悬挂距离/姿态、受力、恢复与极端几何阻挡兜底，需要程序提出方案并通过原型验证。

### D-04｜抓取者可被鱼缸合理带动 — A（已确认）
- 场景：多名玩家已建立抓取关系，部分玩家推动鱼缸前进，另一名抓取者未按移动键或主动输入不同方向。
- 规则：鱼缸可以在有效抓取约束内**被动带动**未主动移动的抓取者；被带动者仍能通过自己的运动意图施加阻力或配合，不变成失去控制的装饰物。
- 相互约束：地形、角色碰撞、其他玩家及抓取点共同限制实际位移；被墙挡住时，不能穿墙、瞬移、无限拉长抓取或把鱼缸弹飞，应合理减速、受阻或偏转。
- 与其他规则一致：只对**已抓取者**适用；未抓取仅头顶支撑者不应被主动水平吸附/拖动（V1.0 §3.2）；正常拉扯不自动脱手（D-02）；踩空未进入死亡区允许有限悬挂（D-03）。
- 未冻结的技术项：被动拖动强度、响应速度、抗阻强度、约束顺应性以及极端卡死的技术兜底，需 M1 原型与四人试玩验证，不代表已确定的物理数值。
- 验收：三名抓取者前进、第四名抓取者不输入方向时，第四名可被合理带动；第四名卡墙时不能穿模，鱼缸应受合理影响；同场景改成第四名**未抓取仅支撑**，不得被鱼缸主动水平拖走。

### D-05｜首版只保留左键长按抓取 — A（已确认）
- 首版抓取输入仅使用**鼠标左键长按**。鼠标右键不承担抓取、保持抓取或松手切换功能。
- 左键在鱼缸底部合法区域**按下瞬间**进行抓取判定（D-01）；抓取成功后持续按住左键维持；松开左键立即解除主动抓取（仍可按头部实际接触提供合法支撑）。
- 已否决的方案：首版不加入“右键点击一次抓住、再点击一次松手”，也不允许左键长按与右键切换两种模式并存。
- 若未来考虑长时间按住左键的疲劳问题，应另行提交需求、评估与确认，不能由程序自行恢复旧方案。
- 验收：鱼缸底部有效范围内测试右键单击、长按，以及左右键交替/同时输入；只有左键按下与松开改变主动抓取状态，右键不留切换状态。

### D-06｜检查点采用“停车入位”激活 — C（已确认）
- **主策划原话（2026-10-09）**：“鱼缸放在4根棉花栏杆上算激活，有点类似开车停进停车位。”
- **冻结规则**：检查点是具有四根棉花包覆柔软支撑栏杆/柱的**安全停放位**。玩家必须把共享鱼缸**实际搬到停车位，并放置在四根支撑上形成有效承托**，才能激活该检查点。
- **明确无效**：角色单独进入停车位无效；鱼缸只是经过、中心越过某条线、完全穿过某个触发面、擦到部分支撑、悬在支撑上方但未有效放置，均不得激活。
- **碰撞关系**：四根棉花支撑属于**安全承托物**，与其合法接触不导致鱼缸碎裂；周围另外配置为危险的墙面/地面仍然接触即碎。支撑不得在鱼缸离开后隔空吸附或永久托举。
- **复位**：第一次成功停放后，这里成为最近激活检查点。后续鱼缸碎裂时，鱼缸在该检查点的四根安全支撑上恢复为静止、安全的可再抓取状态；四名角色按原重生规则复位。不能因为鱼缸在复位时处于该支撑上而反复触发额外检查点事件。
- **未冻结的实现/体验细节**：四处承托如何检测、停稳的必要程度与容差、栏杆几何尺寸、是否必须先松开左键，以及停车反馈样式，由程序给出方案与可视化试验后交主策划验收；**不得自行改回穿线式检查点**，也不得暗中把“放好”变成磁吸/强制对位。
- **验收**：仅穿过停车区域不激活；单独触碰一两根支撑或仅悬在上方不激活；确实放到四根安全支撑上可激活；之后碎缸返回本停车点并正常重新抓取。可观测实际四点接触/支撑状态及激活原因。
- **覆盖旧文档**：本项是主策划对 V1.0 §6.2 “鱼缸本体经过检查点有效区域即激活”和相关 AT-23、AT-40 的后续明确修订；原文件保留作历史基线，以本条最新确认规则为准。

### D-07｜真实可见危险接触即碎，不设玩法容错 — A（已确认）
- **主策划选择（2026-10-09）**：方案 A；危险接触按“真实可见接触即碎”执行，不因轻擦、低速度或小冲击而豁免。
- **正式规则**：共享鱼缸的可见外表面与标记为危险的墙壁、地面、天花板及硬质物体发生实际有效接触，即触发破碎与全队复位。低速擦边、玻璃角部轻碰也一样；不设置仅为了原谅真实接触的玩法层面容错，不改为速度/冲量阈值判定。
- **公平性要求**：碰撞体尽量匹配可见鱼缸边缘；不得让未发生可见接触的隐形扩大碰撞体频繁触发碎裂。允许仅为排除浮点数误差、物理求解噪声及联网修正引起的不可见伪接触采取技术修正，但**不得因此忽略真实、可见的危险接触**。
- **安全接触例外不变**：合法的玩家头顶/抓取支撑、D-06 的四根棉花安全承托栏杆不触发碎裂；危险/安全接触对象应有可配置的明确分类。
- **实现与验证**：程序负责提出碰撞体精度、接触有效性检测、网络权威判定、事件去重和日志方案；主策划验收画面与判定是否一致。不预先虚构毫米、速度、延时等具体技术阈值。
- **验收**：低速擦墙和角部轻碰都碎；近距离但未真实接触不碎；接触安全栏杆不碎；四端对同一次危险接触只有一次一致的破碎/复位，日志记录接触对象与位置。

### D-08｜确认断线后解除连接、剩余三人继续 — B（已确认）
- 场景：原本由四名真人参与的一局游戏中，某位玩家被联机系统**确认断线**。短暂卡顿是否构成断线，以及检测阈值、权威端和状态同步方式由程序评估；未确认断线前的处理尚未冻结。
- 抓取与支撑：一旦确认断线，立即撤销该玩家的**主动抓取关系和头顶支撑资格**；该玩家不再施力，也不得因为断线实体残留持续阻挡或持续牵引鱼缸。**断线不是普通玩家松开左键后继续头顶支撑。**
- 鱼缸连续性：保留鱼缸在断线判定发生时已有的位置、姿态、线速度和角速度，不因断线自动扶正、锁定、复位或瞬间抹除惯性；解除该玩家连接后，后续运动由其余有效玩家和环境决定。
- 继续游玩：其余三人保持当前游戏进程，允许尝试救援和继续前进。不会仅因断线而暂停、全队失败或重置检查点；鱼缸若**随后**触碰危险环境，仍照常触发碎裂和全队复位。
- 人物实体：离线玩家的移动/碰撞代理不得制造卡死、幽灵支撑或额外力；具体何时停用/移除角色实体、如何避免突然物理冲量，由程序提出稳定方案。
- 范围边界：仅要求“四人局中途掉一人，三人仍可连续测试”；**不等于**首版必须支持三人开局、三人关卡平衡、AI 补位或完整断线重连。重连后的出生/抓取/控制权归属等规则仍待另行确认。
- 联机一致性：断线判定与清理应由同一权威流程确认，各客户端最终看到同样的断线玩家状态和鱼缸运动；不得反复释放同一抓取或清除其他人的连接。
- 验收：四人抓取运输过程中让一人断线，检查剩余三人能继续；鱼缸保持既有运动趋势而非突然归零，断线者不再抓取/头顶支撑/施力；后续碎缸与复位仍统一生效；关键事件记录可追踪。

### D-09｜M2 必须支持四名真人异地互联网联机 — B（已确认）
- **主策划选择（2026-10-09）**：方案 B；在 **M2 里程碑交付验收时**，四名真人需要分别使用独立电脑，通过互联网、在**不同网络环境**连接至同一局，共同搬运一个共享鱼缸。仅局域网、多开窗口、模拟输入或脚本控制，不满足 M2 的最终验收。
- **M1 可用临时验证手段**：可以使用本地多实例、同网测试与模拟输入调试物理，但这些不等于已经完成 M2；M0 即须评估异地联机所需的网络架构、连接和同步风险，尽早进行远程网络技术试验。
- **必须保证的行为**：四人看到同一个权威共享鱼缸和一致的抓取、头顶支撑、角色运动、危险碰撞、停车式检查点激活、死亡、鱼缸碎裂与重置结果；不能因为网络校正频繁产生不合理瞬移、物理爆炸或错误碎裂。与已确认 D-08 的断线清理、三人继续游戏规则兼容。
- **不进入本阶段的产品化功能**：M2 不强制商业级匹配、大厅、Steam 邀请、公开服务器或成熟账号体系。房间码、临时连接方式、受控测试部署均可由程序提出，只要真实异地互联网四真人可参与并通过测试。
- **尚待程序评估**：权威状态所在位置、连接方案、网络同步与校正、不同延迟和丢包条件下的表现、连接限制、测试步骤以及相应日志。**未指定固定网络延迟数值或性能阈值**，由程序提出可测试的指标和测试环境，并经主策划评审。
- **验收**：在不同互联网网络下由四名真人分别操作，完成至少一轮抓取、四人施力、转弯/移动、鱼缸碎裂与复位的一致性测试；测试过程及各端状态/日志可复现、可排查。更复杂的连续三段白盒仍属于 M3。
- **对 V1.0 的影响**：补充并收紧 §8.2 和 M2 的“测试连接方案/本地多实例、局域网、异地联机”等开放选项；不修改 M1 物理验证范围，也不把 M3 的三段完整关卡提前归入 M2。

### D-10｜仅严重技术异常允许自动复位 — A（已确认）
- **主策划选择（2026-10-09）**：方案 A；游戏遇到确实无法从正常玩法操作中恢复的严重技术异常时，允许由系统自动将全队与鱼缸复位到最近检查点，以避免永久软锁。
- **不能触发自动复位的正常玩法状态**：鱼缸卡在狭窄转角、四人互相拉扯、角色被合法地形阻挡、玩家主动停止或正在沟通/尝试松手换位救援。**鱼缸长时间不移动，单凭静止时间不能认定为技术异常。**
- **可作为自动兜底候选的异常**：鱼缸掉出有效地图并无法按正常规则恢复；物理状态出现可客观识别、已确认不可通过正常操作解除的异常（例如约束求解进入不可恢复的非法状态）。具体检测方式、触发条件与误报控制由程序提出并实测，不虚构固定时间、距离或数值阈值。
- **自动复位要求**：必须记录可追溯的异常类别、触发依据、位置、时间和相关角色/鱼缸状态；复位行为与已确认的最近检查点、四根棉花支撑和全队状态清理规则保持一致，网络各端统一执行同一次复位，不得出现重复复位或瞬间二次碎缸。
- **失败与异常不得混同**：鱼缸真实接触危险环境必须按 D-07 正常碎裂失败；严重技术异常自动复位属于工程兜底，不应被算作正常玩家碰撞失败。不得借此替玩家自动纠偏、脱困、传送跨越障碍。
- **无法可靠识别的情况**：保留测试版本的手动复位途径；在无法区分正常困难与技术异常时，不允许系统仅凭“似乎卡住了”自行复位。
- **验收**：可正常脱困的卡角与长时间不动不会自动复位；可确认严重技术异常能够触发一次可追溯、各端一致的最近检查点复位；自动复位原因在日志中与真实危险接触碎缸区分。

### D-11｜先制作一套可调白盒比例，试玩迭代 — C（已确认）
- **主策划选择（2026-10-09）**：方案 C；程序**先制作一套合理的角色与鱼缸白盒比例**，供主策划实际试玩后逐步调节；首轮**不要求**另行准备 2–3 套并列候选，也**不要求**主策划先指定固定几何尺寸。
- **首轮需要真实可测**：四名角色能够在鱼缸下方接近、抓取、移动、换位、转弯、跳跃并尝试救援；不得为适配最初比例擅自将抓取位置固定为四角。
- **必须方便调节和复现**：角色身高/碰撞体、鱼缸长宽高、鱼缸底面托举高度、底部合法抓取区域及四根安全支撑栏杆的间距/高度等核心尺寸，应集中参数化；每次测试记录参数值或版本号，避免发生“调过但不知道改了什么”。
- **冻结的是工作方式，不是固定数值**：程序第一版几何只是**临时开发基线**；后续依据换位、转角、跳跃、碰撞与悬挂救援的实机表现，由主策划确认是否继续沿用或调整。质量/惯量、约束容差等物理参数同样不得因使用初稿模型被冒认为最终定值。
- **交付与验收**：提供一套可运行的白盒场景，显示当前比例/配置；能在不大规模改代码或重做场景的情况下更改尺寸并复测同样的核心交互。至少保留一次参数变更前后的记录，用于验证确实可调。
- **与原文关系**：这是对 V1.0 §9 参数化调试和补充文档 §3 的实施方式细化，不改变核心玩法、抓取范围规则、四人联机和阶段验收要求。

### D-12｜抓取、支撑、失败必须有游戏内可见反馈 — A（已确认）
- **主策划选择（2026-10-09）**：方案 A。首版对**抓取成功、仅头顶支撑、抓取失败**提供清晰、可见、彼此可区分的状态反馈；不能仅把关键状态放在程序内部调试面板。
- **抓取成功**：玩家可以从自身视角判断当前主动抓取已建立，可以通过角色/抓取点临时标记、简化动作或状态提示呈现。
- **仅头顶支撑**：与主动抓取显著区分；玩家不会错误以为自己能主动水平驱动鱼缸。
- **抓取失败**：此次左键按下不建立抓取，应有简洁反馈；至少让玩家能识别位置/范围不合法或其他状态不允许抓取（对应 D-01 的按下瞬间判定）。
- **首版表现方式**：允许临时颜色、抓取点标记、简单动作、简短文字提示的组合；具体色彩、UI 样式、美术动画和音效不冻结，交给程序以低成本方式做出可读原型并由主策划试玩确认。
- **状态一致性**：可见反馈必须反映实际权威游戏状态，松手、死亡、断线、碎缸、复位或抓取失败后不能残留“已抓取”假提示；远端玩家所见关键状态不得与最终结果长期冲突。
- **验收**：AT-55～AT-58；用无需打开程序内部日志的四人试玩验证区分三类状态，另用调试日志核对显示与实际状态一致。
