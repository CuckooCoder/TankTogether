## 2. 核心交互边界补充（程序应逐项给出试验结果）

### E-01｜左键按下、预按住、松手后的状态【已确认 D-01 + A + T】

**原文已明确**：有效底部范围才能抓；按住维持；松开立即解除。此前原文未明确“在范围外预按住，之后走进范围”的触发时机。

**D-01 已确认 A（2026-10-09）**：只在**左键按下的瞬间**进行一次抓取判定。若该瞬间角色不在鱼缸底部的有效抓取范围内，或不满足其他抓取条件，本次按下无效。持续按住并进入有效范围**不会自动抓取**；必须先松开、再重新按下左键，才能重新判定。

**按下时成功**：建立主动抓取，持续按住时按 E-02/E-03 的约束保持；**松开时**立即解除主动抓取，不能沿用旧抓取点。若玩家此时仍以头部有效承托鱼缸，则可转成仅支撑而非强行取消实体接触。

**已否决的方案 B**：持续按着左键、进入有效范围自动抓取，首版不得使用。若未来希望改善新手体验，应先提出变更并获得主策划确认。

**D-05 已确认 A（2026-10-09）**：首版**仅保留鼠标左键长按抓取**；右键点击切换抓取的旧方案**不进入首版**。左键在合法范围内按下建立抓取、保持按住维持抓取、松开立即解除主动抓取；鼠标右键不承担抓取/松手功能。若未来重新加入切换抓取，必须另行确认右键与左键的状态优先级，不得由程序默认叠加。

**必须可观察**：按下时的抓取判定成功/失败、是否仍按住、失败原因（不在范围/状态不可抓等）。具体检测尺寸、实现方式及正式 UI 样式仍待原型验证。

### E-02｜正常拉扯时，角色与鱼缸谁限制谁【A + 已确认 D-02/D-04 + T】

**原文已明确**：玩家的 WASD 是移动意图，不代表一定实现位移；鱼缸被限制时，抓取者不能自己跑远，不能形成无限长的隐形绳子。四人的输入都应参与结果。

**最低外在结果**（不指定具体物理实现）：

1. 前进玩家推动/牵引鱼缸时，角色本身也受到鱼缸运动和其他玩家的反作用限制。
2. “三人前进、一人后退”要体现阻力或可解释的旋转，且与抓取点位置相关；不得直接忽略少数人的输入。
3. 某人被墙或队友卡住时，其角色不得持续穿透、鱼缸不得积累无限力然后爆炸。
4. 不为解决多人冲突而偷偷让单人获得鱼缸的绝对控制权。

**D-02 已确认 A（2026-10-09）**：正常多人拉扯时，持续按住左键不会仅因张力较大而自动脱手；优先通过限制角色位移、鱼缸运动及其偏转处理冲突。死亡、主动松手、碎缸/复位例外；极端不可恢复异常的工程兜底需要记录并另行评审，不得用于普通拉扯。

**D-04 已确认 A（2026-10-09）**：已抓取角色可以在有效抓取约束下，被运动的鱼缸合理地被动带动（即便自己未按 WASD）；该角色仍可主动施加阻力或配合，不能视为失去控制。被墙体、队友或地形阻挡时，抓取关系的限制须反向影响鱼缸，让其合理减速、受阻或偏转，不允许穿墙、瞬移、无限拉长约束及异常弹飞。具体拖动强度、速度、主动抵抗程度和异常兜底须在 M1 进行物理实验，**尚未冻结数值**。未抓取、仅有头部支撑的人不适用此主动抓取拖动规则（仍应按 §3.2 自行跟随）。

**程序要提交**：至少 4 个录屏：四人同向、三顺一逆、两侧反向、抓取者被墙阻挡；附上每种情况实际角色移动与鱼缸姿态的说明。

### E-03｜抓取能否被动断开、边缘坠落时如何处理【A + 已确认 D-02/D-03 + T】

**无争议强制断开情形**：松开左键、该玩家进入角色死亡区并触发死亡/重生、鱼缸碎裂/全队复位。旧抓取约束必须及时清除，不能复位后残留。

**D-02 已确认 A（2026-10-09）**：正常多人拉扯、转弯、受阻时，不能仅因外力较大自动脱手；应限制实际运动并保留每名玩家对鱼缸的影响。

**D-03 已确认 A（2026-10-09）**：抓取者踩空并离开道路边缘后，若仍按住左键、未进入死亡区，且抓取关系仍在**合理可实现的有限范围**内，可继续悬挂于鱼缸下方；失去头顶支撑或正常站姿**本身不构成松手条件**。鱼缸继续受该抓取关系及玩家的动作/重量影响，队友可尝试救援。不得借此实现无限距离的绳索或隔空抓取。

**待技术实验与主策划复核的边界**：悬挂允许的几何距离、姿态、受力与恢复方式；当极端几何阻挡导致约束不可恢复时的异常兜底。不得把正常拉扯或普通踩空直接判为强制脱手。任何异常解除须可观测并记录原因。

**新增验收方向**：一名抓取者踩空、未进入死亡区，继续按住左键时可维持有限悬挂；其他三人有实际救援空间；进入死亡区后抓取解除，本人单独重生，鱼缸和其他玩家不自动复位。

### E-04｜单纯头顶支撑与侧向身体碰撞【A + T】

**必须区分**：

- 玩家头顶贴住鱼缸底部：提供垂直承托及上升时顶升，**不提供与抓取等价的主动水平驱动力**。
- 玩家没有抓取但 WASD 跟着移动：需要自行追上鱼缸；不能自动被鱼缸水平“吸附拖走”。
- 身体侧面或其他非头部部位发生接触：是否造成被动阻挡可以由物理模型处理；不得成为绕开左键抓取的强力侧推搬运方案。

**待实验**：通过何种碰撞过滤与接触约束，把“允许被动阻挡”和“禁止无抓取主动推动”分开；重点防止侧推比正常抓取还高效。

### E-05｜全部松手、一个人独撑、无人触碰【A + T】

区分三种场景，不可混成一个“静止”状态：

1. **四人全部松开但头仍顶着**：鱼缸可继续受头部支撑并保留原有水平惯性；原动量按阻尼/接触自然衰减。
2. **只剩 1 人在重心附近抓住或支撑**：可短暂维持或极慢纠偏，但不保证救回严重倾斜，也不可变成一人高速稳定搬运。
3. **没有玩家或合法支撑物接触**：鱼缸继续受重力、惯性和合法环境约束，不得永久悬浮。

**程序要验证**：三个场景在长时间运行中都不会静止锁死、突然弹飞、无因漂浮；是否保住由受力与碰撞结果决定，不强行做“少于两人立即失败”。

### E-06｜跳跃/落地/蹲下的多点上下约束【A + T】

- 非抓取跳跃要有实际触碰才能顶升；不能隔空抬高鱼缸。
- 抓取跳跃的传力更稳定；错时跳跃可造成局部上升与倾斜，但不能强制同帧成功或失败。
- 已抓取者落地后若抓取点仍高于角色头部，要通过有限、可解释的约束和受力处理，不得强制瞬移人物或鱼缸。
- 抓取时蹲下可以产生**有限**下拉；未抓取蹲下只能降低/失去支撑，不能主动向下拉。
- 具体允许的高度差、力限制、空中修正能力均为可调实验参数，不在此定义最终数值。

**必须试验的三个组合**：四人同步跳、两人先跳两人后跳、三人落地一人仍在空中。记录异常受力及能否人工纠偏。

### E-07｜危险碰撞：判定、视觉与例外【A + 已确认 D-07 + T】

**D-07 已确认 A（2026-10-09）**：鱼缸可见外表面与危险墙壁、地面、天花板及硬质场景物体发生真实有效接触，即立即碎裂，**包括极低速擦边或玻璃角部轻碰**。不设置玩法层面的擦边容错，不以速度、冲量或触碰力度决定是否碎裂。合法头部/抓取接触与 D-06 的四根棉花安全支撑栏杆仍不碎；失败日志要记录具体对象、位置和时间。

**不能擅自修改的规则**：不得为了掩盖物理不稳定，把“接触即碎”改为“速度达到阈值才碎”、隐藏的玩法擦边豁免，或把危险墙体统统改为安全物体。碰撞体与画面不一致引起的“隔空碎缸”是技术缺陷，不是玩家失误。

**由程序提出可调方案**：

- 危险碰撞层/安全支撑层/玩家接触层的明确分离。
- 碰撞体与可见鱼缸外表面的几何对应。
- 对浮点误差、轻微穿透、联网位置修正的容差和去重机制；候选容差**只消除看不见的技术误判，不应宽恕真实可见接触**。
- 破碎触发后按同一失败事件只执行一次，防止多次复位、二次碎裂。

**技术验证边界**：低速擦墙与倾斜玻璃角触墙已确认都要碎，**不是待主策划重新选择的玩法容错项**。程序需通过紧贴但未碰、真实接触、接触安全支撑物、多人同步校正等场景展示检测可靠性；浮点/求解/网络噪声修正仅能排除不可见伪接触，不得放过真实可见触碰。误差的具体数值仍待实验，不能伪称已冻结。

### E-08｜“停车入位”检查点、安全支撑和复位【已确认 D-06 C + A + T】

**D-06 已确认 C（2026-10-09）**：不采用“鱼缸中心过线”或“鱼缸全部过线”触发检查点。**四根棉花包覆的柔软栏杆/支撑柱构成一个停车位，玩家将鱼缸实际放在这四根支撑上，形成有效承托，才算激活检查点。** 类似把车停进停车位。

**禁止的误判**：只让人物走进停车位、只让鱼缸穿过停车区域、鱼缸只是碰到其中部分支撑、仅悬于上方或被抓取者从上方掠过，不算完成停放；不得用中心点或整个包围盒穿过触发面代替停车判定。

**正常状态与复位**：
- 四根棉花支撑是合法的安全物理承托物；鱼缸与其接触不碎。其他标记为危险的环境物仍按接触即碎处理。
- 完成停放后，此处成为最新检查点；全队碎缸时鱼缸恢复到四根支撑上，清除旧速度、角速度、旧抓取关系，角色在此附近重生。
- 放在起点/已激活检查点上的初始鱼缸，不应产生反复激活事件。离开支撑后也不应受无形磁吸或远程牵引。

**程序须提出并演示（不是已定参数）**：四根支撑是否都有有效承托的物理/状态判据、停稳容差及必要的检测稳定性、柔软支撑的碰撞层、定位提示、停车成功反馈、倾斜停放或反复弹跳的边界处理。是否必须松开左键才算“放好”**尚未经主策划确认**，不得作为隐藏硬门槛自行添加。

**需求覆盖说明**：本 E-08 + D-06 是 V1.0 §6.2 的后续确认修订；AT-22 保留“人物单独不激活”，AT-23 及补充 AT-40 按“停放并有效承托”验收。除触发方式外，V1.0 的其他检查点/重生原则仍有效。

### E-09｜死亡、断线、全队失败与状态竞争【A + 已确认 D-08 + T】

**原文硬规则**：

- 单人掉落：立即解除本人的抓取/支撑，只有该玩家在最近检查点重生；鱼缸和其他人不回滚。
- 鱼缸危险接触：全队失败，全员和鱼缸回最近检查点；鱼缸恢复安全初始状态。

**程序技术必须解决**：当“玩家死亡、碰墙、检查点停车激活、联机消息晚到”发生在很近的时间内，所有客户端只能认可同一份最终事件次序；不得各自激活不同检查点或执行多次破碎复位。

**D-08 已确认 B（2026-10-09）**：在**确认玩家断线**后，移除其有效抓取和头顶支撑资格，该玩家不再对鱼缸持续施力、牵引或阻挡；其余三名玩家在原有游戏状态下继续游玩，不能因断线直接暂停、全队失败或复位。鱼缸此前已有的位置、姿态、线速度、角速度和检查点记录应保留，不因掉线自动归零或扶正。断线后的鱼缸依然遵循原碰撞碎裂规则。**该处理不同于普通松开左键后仍能头顶支撑。**

## 7. 开工/冻结门槛：两种“可以开始”不是一回事

### 7.1 可以立即开始的事情

- **立项技术评估（M0）**：阅读 V1.0 和本补充文档，提交测试方法、技术风险和备选方案。
- **最小实验场（M1 的部分内容）**：使用标记为 B 的临时方案做四人输入模拟、抓取与运动试验，但必须把临时假设写进构建版本说明。
- **基础技术验证并行工作**：同步开展单机控制、共享鱼缸权威状态的联机可行性验证，不必等待正式地图。

### 7.2 尚不能宣布完成的事情

- **D-01～D-12 已全部确认**，但停车实际交互、掉线后复位人数、断线权威状态、终点完成规则等仍需明确；关键物理参数与联网一致性尚未经实机验证，不能宣布“首版全部规则和技术方案已冻结”。
- 没有四名真人联机实测，不能宣布“首版多人核心机制已验收”。
- 没有独立《关卡策划案》和实测尺寸，不能宣布“连续三段白盒已具备可直接按图搭建的完整设计”。
- 没有灰盒试玩，不能宣称“核心乐趣、事故密度和技术复杂度已通过立项质检”。

### 7.3 建议审查节奏

1. **主策划确认 D 项**：D-01～D-12 已全部确认；按复核台账解决新发现的影响实现的边界问题。
2. **程序交 M0**：按第 6 节评估，明确仍待验证的技术风险。
3. **M1 只做最小运动实验**：一片平地、四角色、一个鱼缸、抓取/松手、多人拉扯与失衡。
4. **主策划试玩复核**：确认是否进入支持头顶、跳蹲、碰撞、复位、联机等后续开发。
5. **再制作三关白盒**：使用真实物理/几何能力设计障碍，避免先做地图再反过来强迫系统迁就。

## 8. 版本维护规则

- 本文为 **V1.12 决策确认后的补充件**，D-01～D-12 已全部确认；仍非所有技术行为均已验证的最终实现规格。
- 如今后新增或更改 D 项，先由主策划明确批准，并同步更新对应 E/AT 和冲突台账；未批准的实验建议不得直接升格为已确认规则。
- 技术方案发生变化时，记录 **影响的可见行为**。只换内部算法但满足 R 项的，不要求修改玩法规则；改变玩家可观察结果的，必须重新评审。
- 严禁同时向程序散发两份互相矛盾却都标“最终版”的玩法文件；对外展示概念文档与程序需求文档有冲突时，应按最新明确确认记录协调。

**本文件最终目的**：在尽可能少的冻结项前提下，把“程序可以自主实现”与“程序不能自行决定玩法”严格分开，使团队从零开发时既不会被不必要的细节束缚，也不会靠猜测填补关键设计空白。
